Provenance of the files in this directory
=========================================

These are the raw artefacts behind every number quoted in the report. They are
included so that the tables in the report can be checked without rerunning
anything.

stage_a.csv            6 feature rows, fixed linear SVM, 5 venue-holdout folds
stage_b.csv            10 feature/classifier rows, same folds; also carries the
                       per-fold columns ba_0 .. ba_4
selection.json         the feature and classifier that were locked
val_metrics.json       validation confusion matrix and per-class metrics
test_metrics.json      test confusion matrix and per-class metrics
test_predictions.csv   one row per test image: filename, group_id, y_true, y_pred
dataset_summary.md     the per-class, per-split counts

They were produced by the run of 2026-10-14.

Two things changed in src/task3/ after that run:

  2026-10-15  the crop cache key gained the image size (s256__filename)
  2026-10-21  comments and docstrings were translated to English; no
              executable statement was changed

Both commands were run again on 2026-10-23 from the code in this archive and
rewrote stage_a.csv and stage_b.csv byte for byte. The replay is what the
stamp file now records, so the fingerprint matches the shipped source and a
rerun resumes instead of asking for --force. A resume no longer re-evaluates
the locked configuration a second time: the already-evaluated row was excluded
from the resume set, which used to append a duplicate of it.

evaluate.py was not rerun. test_metrics.json, test_predictions.csv and the
numbers of Section 4.4 remain the single 2026-10-14 evaluation.

Because the replay rewrote them from the code in this archive, the fingerprint
in run_stamp.json matches that code, and a plain

  python -m src.task3.run_stage_a
  python -m src.task3.run_stage_b

reuses the tables above instead of asking for --force. The guard still fires
when splits.csv or src/task3 is edited after the stamp was written, which is
what it is for: a stale table is never quoted as a fresh result.

No new training run produced a different number, and the test set was scored
once.
