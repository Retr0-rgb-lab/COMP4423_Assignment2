## 1. 类别定义及其应用

本作业为二分类：**inside = 1**（拍摄于 PolyU 主校区内）、**outside = 0**（拍摄于主校区外）。标签依据**相机位置与画面主体所在的地理侧**判定，不依据画面是否在室内、是否为彩色，也不依据红砖、logo 或外观风格。

| 规则 | 内容 |
|---|---|
| 地理范围 | 以 PolyU 官方 Campus Map 为准。**仅主校区为正类**；PolyU 校外附属场所、附属学院场地一律标 outside |
| 室内外无关 | 「inside/outside」指地理范围，不指 indoors/outdoors。商场、医院、图书馆中庭等室内场景按其是否在主校区内判定 |
| 边界排除 | 排除校门与门槛位置、连接天桥与空中连廊、校园边界上的不确定位置、跨越边界取景的视角 |
| 视角一致性 | 相机位置与画面主体场景必须明确位于边界同一侧 |
| 视觉输入 | 采集 scene-level 场景照，画面保留环境上下文；不拍孤立物体、不拍屏幕或照片的照片 |
| 像素限定 | 分类器仅使用图像像素。GPS / EXIF、文件名、文件夹名、外部地理查询不得作为特征，仅可用于确认 ground truth |
| 拍摄合规 | 只在允许拍摄的区域拍摄，避免可识别人物、个人信息、限制区域 |

### 1.1 实际执行中的边界判定

边界排除不是形式条款。校内主入口区域的采集**剔除了 11 张**：

- **校名牌位置 4 张** —— 相机站在校门入口，无法明确判定在校内还是校外
- **有盖通道闸机 7 张** —— 闸机即门槛；且画面含近距可辨人物，两项均违反规则

保留的是校门内侧的草坪花园、校园钟塔、主入口广场等主体明确在校内的取景。

## 2. 分组口径

**一个物理场所 = 一个 `group_id`**，是 train / val / test 的划分单元。

PDF 的口径是「同一庭院、**建筑或地标**的邻近取景归为同一地点组」。据此判定时**只合并真正相邻的取景，不合并同一片区域内彼此分离的独立建筑**：

- 港大的「现代教学楼群」与「Main Building 传统红砖区」分处校园两端，是两栋不同建筑 → **拆为独立组**
- 西九的「M+ 博物馆」「Art Park」「維港海濱长廊」分处三个地点、中间有道路相隔 → **拆为独立组**
- 校内的连续走道（P/Q 區藻井走道、J–VA 走道）互不可分割 → **保持单组**

场所内部的多样性由四列记录，不单独成组：

| 列 | 含义 | 用途 |
|---|---|---|
| `group_id` / `location_name` | 物理场所 | **划分单元** |
| `sub_area` | 场所内部的位置分区 | 场所内部分析 |
| `scene_class` | 受控场景类别（13 类） | 场景多样性交叉分析 |
| `status` | include / exclude | 入库筛选 |

**受控场景词表（13 类）**：建筑立面、建筑入口、室内空间、廊架连廊、林荫步道、绿地、铺装广场、坡道台阶、道路界面、水体、街市摊位、城市远景、施工围挡。

## 4. 四轴变化方案

| 维度 | inside（每组 35 张） | outside（每组 38 张） | 拍法 |
|---|---|---|---|
| 视点 | 24 | 26 | 6 个站位 × 约 4 张 |
| 距离 | 6 | 6 | 2 个站位各拍近 / 中 / 远 |
| 近景 | 5 | 6 | 墙地面交界、材质细节，**必须保留空间纵深** |
| 光照 | 2（夜间） | 2–4（夜间） | 见下 |
| 背景 | 覆盖全部 | 覆盖全部 | 每组至少 3 类 |

**视点**按三维度铺开而非随手移动：

| 维度 | 取值 |
|---|---|
| 方位 | 正面 / 斜 45° / 侧面 |
| 机位高度 | 地面 / 微仰 / 俯视（台阶或坡道上方） |
| 横移 | 主体在画面左 / 中 / 右 |

同一站位内的照片朝**同一方向**，只调构图（主体占比、留白、地平线位置）；连拍时锁定 AE/AF。

**背景**每组至少覆盖 3 类（建筑立面 / 绿化 / 水面 / 铺装 / 周边车流），且**校内与校外使用同类背景并存** —— 例如「红砖立面」在 IN-03 校內紅磡樓与 OUT-06 港大 Main Building 两侧都出现，「现代幕墙 + 大面积铺装」在 IN-04 泳池段与 OUT-02/OUT-05/OUT-08 两侧都出现。

**四轴全部在组内变化，不构成独立分组** —— 若某一轴单独成组，划分会退化为按该轴划分。

### 6.3 已知局限（须写入报告 Task 2 / Task 4）

- **地点组数量有限**：outside 9 组、inside 7 组，20% 的测试集最多容纳 2 个场所组，测试指标的解释力受限。须在报告中说明这是分组数量而非图片数量带来的限制。
- **OUT-07（港大校园绿地）仅 7 张**，不足以独立支撑一个 split 单元，是划分比例偏离 60/20/20 的直接原因。
- **类别分布不均**：建筑立面与廊架连廊合计占 262 张（36%），水体仅 19 张。评估时须按类别而非仅按图片数报告指标。
- **道路界面偏斜**：inside 10 张 vs outside 57 张。该场景在校外有大量街市素材，校内受限于车行道拍摄条件。若不补充校内道路界面，模型可能学到「密集车流 = outside」。
- **室内样本仅 5 张**：全为港大走廊，且仅在校外侧。模型对 indoors/outdoors 的混淆只有单侧证据。
- **施工围挡为临时场景**：两侧各 14 / 5 张，数年内会发生变化，须作为数据集耐久性局限披露。
- **夜景比例偏高**：inside 10.1% / outside 13.6%，略高于 5–8% 的理想区间。两侧比例接近，但仍需在 Task 4 讨论。

## 7. 泄漏防控

- 一个物理场所 = 一个 `group_id`，是 train / val / test 的划分单元
- **互见组绑定同 split**：OUT-05（M+ 博物館）与 OUT-08（Art Park）隔一条路互相通视，被约束绑定进同一个 split
- 同一场所的连拍、复访、昼夜取景、视频帧、修饰副本全部留在同一组同一 split
- 数据增强仅在划分之后、仅对训练集施加
- **地点组为不可分割单元**，抽稀在组内等距取样，保留视点跨度
- 脚本 `src/tools/build_dataset.py` 每次运行自检：无组跨 split、互见组同 split、每个 split 两类齐全，不通过即报错退出
