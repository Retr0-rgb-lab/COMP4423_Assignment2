## 1. 类别定义及其应用

本作业为二分类：**inside = 1**（拍摄于 PolyU 主校区内）、**outside = 0**（拍摄于主校区外）。标签依据**相机位置与画面主体所在的地理侧**判定，不依据画面是否在室内、是否为彩色，也不依据红砖、logo 或外观风格。

| 规则 | 内容 |
|---|---|
| 地理范围 | 以 PolyU 官方 Campus Map 为准。**仅主校区为正类**；PolyU 校外附属场所、附属学院场地一律标 outside |
| 室内外无关 | 「inside/outside」指地理范围，不指 indoors/outdoors。商场、医院、图书馆中庭等室内场景按其是否在主校区内判定 |
| 边界排除 | 排除校门与门槛位置、连接天桥与空中连廊、校园边界上的不确定位置、跨越边界取景的视角 |
| 视角一致性 | 相机位置与画面主体场景必须明确位于边界同一侧 |
| 视觉输入 | 采集 scene-level 场景照，画面保留环境上下文；不拍孤立物体、不拍屏幕或照片的照片 |
| 像素限定 | 分类器仅使用图像像素。GPS / EXIF、文件名、文件夹名、外部地理查询不得作为特征，仅可用于确认 ground truth |
| 拍摄合规 | 只在允许拍摄的区域拍摄，避免可识别人物、个人信息、限制区域 |

## 2. 分组口径

**一个物理场所 = 一个 `group_id`**，是 train / val / test 的划分单元。

采用保守口径而非细分组：组切得越细，测试集的有效样本量越大，但同一处场所被拆到不同 split 的泄漏风险也越高。以场所为单位划分，从结构上杜绝「同一场景跨 split」。

场所内部的不同场景不单独成组，改由两列记录，供报告做系统性分析：

| 列 | 含义 | 用途 |
|---|---|---|
| `group_id` / `location_name` | 物理场所 | **划分单元** |
| `sub_area` | 场所内部的位置分区 | 场所内部分析 |
| `scene_class` | 受控场景类别（13 类） | 场景多样性交叉分析 |
| `scene_type` | 具体画面内容 | 人工核对 |
| `status` | include / review / exclude | 入库筛选 |
| `notes` | 地点锚点、剔除原因、待确认项 | 审计 |

**受控场景词表**：建筑立面、建筑入口、室内空间、廊架连廊、林荫步道、绿地、铺装广场、坡道台阶、道路界面、水体、街市摊位、城市远景、施工围挡。

## 7. 泄漏防控

- 一个物理场所 = 一个 `group_id`，是 train/val/test 的划分单元
- 同一场所的连拍、重复访问、视频帧、修饰副本全部留在同一组
- 场所内部的位置分区（`sub_area`）**不作为划分依据**
- 数据增强仅在划分之后、仅对训练集施加
- 报告中给出每类、每 split 的实际图片数与地点组数
- 划分按场所约 60% train / 20% val / 20% test，每个 split 两类均有代表

> **组数偏少的代价**：outside 目前只有 4 个场所组，20% 的测试集最多容纳 1 个场所，测试指标的解释力有限。inside 采集完成后（12 个机位组），两类合计 16 组，测试集可容纳 2–3 个场所/类，指标才具可解释性。这是 inside 必须尽快开拍的原因。
